# Migrate the existing site to static hosting

Read-only AWS inspection on 2026-11-08: `www.jiejiechen.com` already points to CloudFront distribution **E1DQTNP78PXVF5** (`d2o1isbaui3xxy.cloudfront.net`). Its only origin is API Gateway `7e9m3xcb0k.execute-api.ap-southeast-2.amazonaws.com`; the distribution is **not** managed in this Terraform repo. Do not create a second distribution with the `www` alias or change DNS. Add a private S3 origin to the **existing** distribution, preserving its certificate and API Gateway origin.

## Protect the source first

RDS `jiejiechen-db` currently has **zero-day automated backup retention**. With user approval, a new encrypted manual snapshot `jiejiechen-db-pre-static-20261114000322` was created and verified **available** on 2026-11-14; keep it through rollback. PostgreSQL port 5432 is currently open to `0.0.0.0/0` (security risk); restrict it after confirming the required access path, separately from the content migration.

Strapi's API Gateway `3i8q0iafa7` returned HTTP 500 during inspection. Its gateway log reported a Lambda service 4xx and there were no recent CMS Lambda logs. Rather than start Strapi against the live database (which could change its schema), the current published content was exported using `jiejiechen-cms/scripts/export-postgres-content.cjs` in a **read-only repeatable-read transaction** over verified RDS TLS. The script retrieves the managed secret in memory, never prints it, selects only public fields and published rows, fails on unsupported block types, and writes `jiejiechen-react/src/content/snapshot.json` atomically. The resulting snapshot has 2 published articles and 3 project pages; a third, unpublished article is excluded. To repeat that export after changes, set `AWS_PROFILE`, `RDS_SECRET_NAME`, `RDS_HOST`, and `RDS_CA_BUNDLE` as in the script's requirements; never print or commit the managed RDS password. If the Strapi schema evolves, update the mapping before re-export. A local SQLite CMS by itself does not contain the existing site content.

## Generate site files

The working-tree static snapshot was generated directly from the RDS source and has passed a full static build. Review and commit it before enabling CI. If the Strapi API is later recovered, you can instead export it with a read-only token from `jiejiechen-react`:

```powershell
$env:STRAPI_URL='http://localhost:1337' # or the actual HTTPS origin
$env:STRAPI_TOKEN='<read-only-api-token>'
$env:MEDIA_BASE_URL='https://cjj-prod-fu4c-strapi-assets.s3.ap-southeast-2.amazonaws.com'
npm run export:content
# Keep existing NEXT_PUBLIC_API_HOST=https://www.jiejiechen.com and public IDP/PostHog settings
npm run build
```

The API exporter paginates published articles/pages with relations and blocks, writes `src/content/snapshot.json` atomically, and fails on an empty article export. Existing absolute S3 media URLs are preserved. Local `/uploads/<key>` URLs become `<MEDIA_BASE_URL>/<key>`; the real S3 bucket has keys at root. **Copy local-only uploads to that bucket first**, keeping object keys, and verify the public media URLs. The current three referenced article/author images all returned HTTP 200 directly from S3. Review the snapshot for private data, missing slugs, SEO and media before committing. `npm run build` generates `out/index.html`, `out/blog/<slug>.html`, `out/page/<slug>.html`, `out/table.html`, `out/oidc-callback.html`, etc. It intentionally fails with an empty snapshot. CMS is not required for serving these files. Future edits require re-export + rebuild + redeploy.
